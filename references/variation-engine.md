# 变化引擎 · Variation Engine（references/variation-engine.md）

> 多候选与批量出章时的变化纪律。核心原则：**变化必须改变视觉语法，而不是只挪位置/换参数**。

## 一、多候选策略（质量不稳定时）

1. 同一输入出 3 个互不相同的概念稿（候选间至少更换：母题转译角度 + 布局族 + 饰件系统）
2. 视觉评审排序（用 quality-gate 逐项打分）→ 选优渲染
3. 不过线则按 gate 意见修订重跑，最多 2 轮（2 轮规则全局共享，见 quality-gate）

## 二、变化维度（每次至少动前两条）

| 维度 | 示例 |
|---|---|
| 母题转译 | 正面纹章像 ↔ 标志物剪影 ↔ 特征符号拼合（如兔耳+黑环） |
| 布局族 | 中央对称 + 双翼 ↔ X 交叉 + 底部字带收口 ↔ 环带包围 + 放射星芒 |
| 饰件系统 | laurel 月桂 ↔ sunburst 放射 ↔ banner 缎带 ↔ star 环阵 |
| 明度分布 | 亮面居中暗线包边 ↔ 暗面居中亮线勾边（保持三档硬明度） |
| 品阶极性 | light-on-dark ↔ dark-on-light（换底色极性不改构图） |

## 三、防重复纪律

- 不默认反复输出"居中主体 + 均匀星芒 + 底部横幅"这一种安全解
- 相邻两张输出至少两个维度不同；批量任务相邻不得共用同一布局族
- 只参考当前会话内可见的最近输出，不臆造"上次的结果"

## 四、密度纪律

- 构图拥挤时先删装饰性次级元素（散点、小花、次要缎带），**不得削弱主母题或破坏固定系统**
- 每次删减后重跑 quality-gate 的 G6（主母题占比）确认未被误伤
